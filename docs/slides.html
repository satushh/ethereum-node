ethereum-node

Geth (execution) + Prysm (consensus) — one binary, one process

  • Both upstream clones unmodified; composed via Go modules (enabled by Prysm's Bazel removal)
  • geth v1.17.4 (exactly what prysm/go.mod imports) + prysm develop
  • ~420 hand-written integration lines, zero upstream changes
  • Devnet-verified: a block every slot, epochs justified & finalized

How it works today

┌──────────────────── ethereum-node (one process) ────────────────────┐
│         supervisor · one datadir · one lifecycle · one log          │
│                                                                     │
│   ┌─ gethapp ───────────┐    Engine API     ┌─ prysmapp ─────────┐  │
│   │ geth node stack     │◀───────────────▶ │ prysm beacon node  │  │
│   │ execution/   devp2p │  private IPC       │ beacon/     libp2p │  │
│   └─────────────────────┘  socket in the     └────────────────────┘  │
│                            datadir — no JWT,                        │
│                            nothing to configure                     │
└─────────────────────────────────────────────────────────────────────┘
                 validator client stays a separate process
  • gethapp: geth's public constructors called from config structs (137 lines)
  • prysmapp: upstream beacon main.go made importable, handed a synthesized argv
  • Engine API semantics unchanged — same JSON, same validation, separate databases & P2P

How to run it

# one clone, one build — clients come from the Go module proxy
git clone https://github.com/satushh/ethereum-node.git
cd ethereum-node && go build -o bin/ethereum-node ./cmd/ethereum-node

# one-command local devnet: genesis + combined node + validator
scripts/devnet-up.sh
tail -f run/logs/node.log      # geth + prysm lines in one stream
scripts/observability-up.sh    # grafana dashboard at :3001

# watch it work
curl -s localhost:8545 -d '{"method":"eth_blockNumber","params":[],"id":1,"jsonrpc":"2.0"}'
curl -s localhost:3500/eth/v1/beacon/states/head/finality_checkpoints
  • One Ctrl-C stops both halves in order: beacon drains, then geth persists state
  • Observed: ~190 MB RSS, <1% CPU for the whole node on an idle devnet
